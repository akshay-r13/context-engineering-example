# Context Engineering — Code Example

Companion code for the Medium article **"Context Engineering isn't that Deep — Simply Explained"**.

This repo contains a LangChain customer support agent built in two versions — naive and optimised — to demonstrate the practical impact of context engineering on token usage and response quality.

---

## What's in this repo

```
├── agent_naive.py          # Baseline agent — no context engineering applied
├── agent_optimised.py      # Optimised agent — focused retrieval, capped tool outputs, trimmed history
├── data/
│   ├── setup_db.py         # Generates the SQLite database with mock orders, products, shipments
│   ├── ecommerce.db        # SQLite database (generated by setup_db.py)
│   ├── policy_document.txt # Verbose ShopNest policy document used for retrieval
│   └── policy_index/       # FAISS vector index (generated on first run of agent_optimised.py)
└── scripts/
    ├── compare_retrieval.py # Side-by-side comparison of naive vs optimised search_policy output
    └── inspect_chunks.py    # Inspect the FAISS chunks stored in the vector index
```

## Setup

### Prerequisites

- Python 3.11+
- [uv](https://docs.astral.sh/uv/) for package management
- A Google Cloud project with the Vertex AI API enabled
- [Google Cloud CLI](https://cloud.google.com/sdk/docs/install) installed and authenticated

### 1. Clone the repo

```bash
git clone https://github.com/akshay-r13/context-engineering-example.git
cd context-engineering-example
```

### 2. Install dependencies

```bash
uv sync
```

### 3. Authenticate with Google Cloud

This repo uses Vertex AI with Application Default Credentials — no API key needed.

```bash
gcloud auth application-default login
```

Then set your project:

```bash
gcloud config set project YOUR_PROJECT_ID
```

Make sure the Vertex AI API is enabled in your project:

```bash
gcloud services enable aiplatform.googleapis.com
```

### 4. Generate the database

```bash
uv run python data/setup_db.py
```

This creates `data/ecommerce.db` with mock products, customers, orders, and shipments.

---

## Running the agents

### Naive agent

```bash
uv run python agent_naive.py
```

### Optimised agent

```bash
uv run python agent_optimised.py
```

On first run, `agent_optimised.py` will build and save the FAISS vector index from the policy document. Subsequent runs load it from disk.

Both agents run as an interactive chat loop. Type `quit` to exit and see the token usage table.

---

## Utility scripts

### Compare retrieval outputs

Run the same query through both the naive (section-based) and optimised (embedding-based) `search_policy` tools and see the difference in output size:

```bash
uv run python scripts/compare_retrieval.py "what is the return policy"
```

### Inspect vector index chunks

See all chunks stored in the FAISS index with their sizes:

```bash
uv run python scripts/inspect_chunks.py
```

## Try these queries

A good 4-turn conversation to demonstrate the token growth:

1. `Hi, I placed an order a few days ago with ID ORD-48291. Can you tell me what's going on with it?`
2. `What's your return policy if I decide I don't want the items anymore?`
3. `Can you tell me what other headphones you have for sale?`
4. `Just to confirm — when exactly is my order expected to arrive and which carrier is handling it?`
